# GitHub + Codex Automation 配置指南

## A. 上传仓库

1. 在 GitHub 新建仓库，例如：`rwe-medicare-policy-tracker`。
2. 将本模板全部文件上传到仓库根目录。
3. 推荐将仓库设为 Private，至少在前期规则和数据结构尚未稳定时如此。
4. 首次提交信息可用：`init: rwe medicare policy tracker`。

## B. 在 Codex 中连接仓库

1. 打开 Codex。
2. 连接你的 GitHub 账号并授权这个仓库。
3. 打开该仓库，新建一个长期线程，建议命名：
   `全国真实世界医保综合价值评价监测`。
4. 确认 Codex 能读取 `AGENTS.md`。

## C. 第一次只做“基线调查”

不要一上来就开 Automation。先手工运行下面这段：

```text
请阅读仓库根目录 AGENTS.md。

这是全国真实世界医保综合价值评价长期监测项目的第一次运行。
本次任务是建立“基线”，允许收录历史信息，不按普通增量任务处理。

请完成：
1. 核验 sources/official_sites.csv 中所有国家和省级医保官方网站；
2. 根据国家医保局《关于开展真实世界医保综合价值评价试点工作的通知》（医保办发〔2025〕15号）核对试点先行地区及任务分工；
3. 核验首批国家可信评价点网络公开信息；
4. 搜集截至今天已经公开的真实世界医保综合价值评价重要政策、试点、项目、评价点及结果应用进展；
5. 建立 data/master.csv 基线；
6. 填充 data/regions.csv；
7. 为已有明确进展的地区建立 provinces/*.md；
8. 生成 reports/YYYY-MM-DD-baseline.md；
9. 所有事实必须保留官方原始URL；
10. 不确定的信息标记待核实。

完成后运行仓库脚本检查格式，并提交一次 commit。
```

先人工检查这次基线结果。重点看：是否误收普通“真实世界研究”、是否把“医保综合价值评价”与其他HTA/药物经济学项目混为一谈、是否保留官方链接。

## D. 建立 Automation

基线确认无误后，在同一长期线程创建定时任务。将 `AUTOMATION_PROMPT.md` 正文作为任务提示词。

建议频率：**每2天一次**。

建议不要固定在凌晨网站维护高峰，可选择上午或下午。

## E. 建议运行纪律

- 第一个月每期人工抽查 5—10 条；
- 一旦发现某省官网改版，更新 `official_sites.csv`；
- 一旦发现新的试点城市/可信评价点，加入高优先级监测；
- 不建议自动下载所有附件，先记录 URL；
- 对重要正式文件再保存本地副本。

## F. GitHub 权限

要实现“自动 commit + push”，Codex 所在环境必须拥有该仓库写权限。
如果只授予读取权限，自动化仍可完成检索和本地修改，但无法推送。

不要把 GitHub Token、账号密码或其他密钥写入仓库文件。
