# AGENTS.md — 全国真实世界医保综合价值评价长期监测规范

## 1. 项目目标

持续监测中国国家、省、市及试点地区“真实世界医保综合价值评价”的政策、试点、评价项目、可信评价点、研究成果和医保决策应用进展。

本项目以“增量监测”为主。第一次运行建立基线；第二次及以后必须先比较历史数据库，再判断是否为新增或实质更新。

## 2. 重点主题

重点关注但不限于：

- 真实世界医保综合价值评价
- 药品真实世界医保综合价值评价
- 医疗服务真实世界医保综合价值评价
- 医用耗材真实世界医保综合价值评价
- 真实世界综合价值评价
- 医保综合价值评价
- 真实世界评价试点
- 试点先行地区
- 国家可信评价点 / 可信评价点网络
- 真实世界研究 / 真实世界证据
- 医保价值评价
- 医保数据支持真实世界研究
- 评价成果库 / 成果入库
- 医保目录、支付标准、集采、挂网、医疗服务价格项目、支付方式改革中的评价结果应用

## 3. 来源优先级

按以下优先级使用和核验信息：

1. 国家医疗保障局官网及其直属机构；
2. 各省、自治区、直辖市医疗保障局官网；
3. 各试点城市医疗保障部门官网；
4. 国家可信评价点、医疗机构、科研机构官网；
5. 政府新闻发布、政府信息公开平台；
6. 官方微信公众号等官方新媒体；
7. 权威行业媒体，仅可作为线索来源。

**原则：非官方媒体不得单独支撑确定性政策结论。**
若官方原文无法找到，记录为“待核实”，不要自行推断。

## 4. 每次运行的固定流程

### 4.1 读取历史状态

先读取：

- `data/master.csv`
- `data/latest.csv`
- `data/regions.csv`
- `sources/official_sites.csv`
- `sources/keywords.txt`
- 最近 2—3 期 `reports/*.md`

### 4.2 检索顺序

先做固定官网扫描，再做全网补漏。

固定官网扫描应至少覆盖：

- 国家医保局；
- 31 个省级医保部门；
- `official_sites.csv` 中标记 `priority=high` 的试点地区；
- 已发现有真实世界医保综合价值评价活动的地区；
- 已发现承担评价项目的可信评价点。

### 4.3 时间窗口

常规运行：重点检索自上次运行时间以来的新发布内容，同时向前回溯 7 天以降低漏检风险。

若上次运行失败或间隔超过 3 天，则扩大回溯窗口。

### 4.4 识别“实质变化”

以下情况应记录为新增或更新：

- 新政策、新通知、新指南、新征求意见稿；
- 新增或调整试点先行地区；
- 新增可信评价点、评价机构或协作网络；
- 新项目启动、备案、入组、实施、结题、发布成果；
- 已有项目从“计划”进入“实施/完成/成果应用”等新阶段；
- 新增数据库、数据平台、监测哨点；
- 评价结果首次被用于医保目录、价格、支付、集采、医疗服务价格项目等决策；
- 官方会议、培训、调研中首次披露明确的新工作安排或时间表；
- 原政策附件、名单或实施要求发生实质修改。

以下通常不作为独立新增：

- 同一新闻的转载；
- 没有新事实的领导调研或宣传稿；
- 仅重复国家层面已有表述、没有本地区新增措施的转发；
- 标题不同但内容实质相同的重复网页。

## 5. 数据库写入规则

### 5.1 master.csv

一行代表一个“可独立识别的事件”。必须尽量填写：

- `record_id`
- `publish_date`
- `discovered_date`
- `province`
- `city`
- `organization`
- `title`
- `category`
- `domain`
- `stage`
- `summary`
- `change_summary`
- `source_url`
- `attachment_name`
- `attachment_url`
- `source_type`
- `official`
- `first_seen`
- `last_seen`
- `status`
- `confidence`
- `notes`

`record_id` 建议格式：
`YYYYMMDD-省份缩写-类别-四位序号`

### 5.2 status 枚举

只允许：

- 新增
- 更新
- 持续推进
- 已完成
- 待核实
- 无变化

### 5.3 confidence 枚举

- high：官方原文直接支持；
- medium：官方二手材料或多方可靠来源支持；
- low：仅线索，尚未找到官方原文。

### 5.4 去重

优先按以下组合判断重复：

1. `source_url` 完全相同；
2. 同一地区 + 同一发布机构 + 同一天 + 高度相似标题；
3. 同一政策文件被多个网站转载；
4. 同一项目的阶段更新不应新建完全重复事件，应在原记录基础上更新 `last_seen`、`stage`、`change_summary`，必要时保留一条新的“阶段变化事件”。

## 6. 省份档案

发生新增或变化时更新 `provinces/<省份>.md`，至少包括：

- 当前总体状态；
- 是否属于试点先行地区；
- 已知试点城市；
- 已知可信评价点；
- 已知评价项目；
- 最新政策；
- 最近更新时间；
- 关键原始链接；
- 待跟踪问题。

## 7. 每期报告

生成 `reports/YYYY-MM-DD.md`。

必须包含：

1. 本期核心变化；
2. 本期新增/更新明细表；
3. 发生变化的重点地区；
4. 全国趋势观察；
5. 待核实事项；
6. 本期无重大变化说明。

**全国趋势观察必须基于本期和历史数据库已有事实，不得把推测写成事实。**

## 8. 附件处理

优先记录原始附件 URL。
只有以下附件值得保存到仓库：

- 正式政策文件；
- 指南/技术规范；
- 实施方案；
- 征求意见稿；
- 评价报告；
- 名单；
- 关键表格。

普通新闻网页不需要下载。

## 9. Git 提交

每次运行结束，如有文件变化：

- 检查 CSV 格式完整；
- 运行 `python scripts/normalize.py`；
- 运行 `python scripts/deduplicate.py`；
- 运行 `python scripts/build_report.py`（如报告尚未生成）；
- 查看 `git diff`；
- commit 信息建议：`monitor: YYYY-MM-DD 增量更新`。

如果当前环境没有 push 权限，不要伪造已推送状态；保留本地 commit，并在结果中说明。

## 10. 最终回答格式

每次 Automation 完成后，用简洁中文报告：

- 本期发现多少条新增、多少条更新；
- 最重要的 3—5 条变化；
- 哪些文件已更新；
- 是否存在待核实线索；
- 是否成功 commit/push。

所有重要事实必须附原始 URL。
